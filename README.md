# 鲸鱼娘桌宠（WhalePet）

> 会看 token 消耗的桌面宠物。底部常驻一条信息条，实时汇总你所有 AI 客户端的用量，每笔扣费都变成一次受击动画。

独立 Windows 桌宠程序，克隆或解压到任意目录，双击即用。除了会动，它还把 **token 消耗变成看得见的反应**：底部常驻一条信息条，实时汇总你所有 AI 客户端的用量——**WorkBuddy、DSH、Codex、Claude Code、ZCode 五个数据源开箱即用**；显示哪几项、按什么顺序显示，都在**设置窗口**里勾选。每笔扣费到账，傻鱼按金额轻重受击（轻痛 → 普通痛 → 暴击）、整只红闪一下，鱼身上还飘出这一笔「掉了多少血」。

**「什么时候播哪个动作」是配出来的，不是写死的。** 动作页按「什么时候播」分成五张卡片 —— 待机随机 / 偶尔眨眼 / 单击摸摸 / 双击 / 扣费反应，每张卡片里放谁、谁就在那个时候播；同一个动作可以同时挂在几个时机上，一个都不挂就是关掉它。所以「双击改成歪头放电」「大额扣费换成打起精神」都不用改代码。

**单位口径**：WorkBuddy 计的是 credit，桌面上按**积分**显示；其余来源（DSH / Codex / Claude / ZCode）一律按 **token** 显示。信息条上还有一个可选的「**今日已用**」汇总字段，把今天各来源的量并排放在一起（token 和积分分开记，**不做汇率式换算**）。某一格**没有数据时不带单位**、只画 `--` —— `-- token` 里的单位纯是噪音。

数据源和字段都是**插件**：想接自己的客户端，把 `providers/_template.js` 复制成 `~/.whalepet/providers/xxx.js` 就多一个数据源；不想要的，在设置里**卸载**（内置插件随时装回来），用户级插件还能直接**删除文件**。

## 启动

```powershell
git clone https://github.com/<你的用户名>/whale-pet.git
cd whale-pet
```

然后**双击 `安装依赖.bat`** 装一次依赖（走 npmmirror 镜像），之后**双击 `启动鲸鱼娘桌宠.bat`** 即可，秒开。

目录放在哪儿都行（D 盘、桌面、任意路径），两个脚本都用 `%~dp0` 取自己的位置。

依赖缺失时（比如 `node_modules` 被删了），启动脚本会主动提示你双击 `安装依赖.bat`。

也可以手动启动：

```powershell
npm install
npm start
```

### 启动脚本的两个坑（改脚本前必读）

这两个坑都会让「双击了没反应」，而且报错信息看着和真实原因完全无关：

**① 必须是 GBK 编码 + CRLF 换行。**
中文 Windows 的 CMD 代码页是 936(GBK)。脚本若存成 UTF-8，CMD 会按 GBK 逐字节配对，把下一行的首字符吃掉，于是 `cd /d "%~dp0"` 变成 `锟斤拷d ...`，报 `不是内部或外部命令` + `系统找不到指定的路径`；若再是纯 LF 换行，多行 `if ( ... )` 括号块解析失效，块内命令会被无条件执行。改完请用 `python tools\make-launchers.py` 重新生成。

**② `%~dp0` 结尾自带反斜杠，不能塞进引号。**
`%~dp0` 展开是 `D:\WhalePet\`，写进引号就变成 `"...electron.exe" "D:\WhalePet\"`——反斜杠把结尾引号转义掉了，引号不闭合，Electron 收到的是非法路径 `D:\WhalePet"`，结果是**只挂一个进程、永远不出窗口**（`tasklist` 里能看到 electron.exe，但桌面上什么都没有）。必须先去掉尾斜杠再传参。

## 交互

| 操作 | 反应 |
|---|---|
| 待机 | 8 帧呼吸循环（挤压以裙摆下沿为锚，所以是「起伏」而不是整体缩放） |
| 眨眼 | 保持当前姿势，睁 → 闭 → 睁（约 0.25 秒），两三秒一次 |
| 随机小动作 | 待机时按权重随机出现：歪头放电 / 原地晃晃 / 打起精神（最后一个少见） |
| 左键单击 | 随机摸摸反应：轻痛 / 普通痛 |
| 左键双击 | 开心：蹲 → 蹦起来眨个左眼 → 落地 |
| 按住拖动 | 跟着光标 1:1 移动，松手回待机并记忆位置 |
| 右键 | 菜单四项：**置顶开关 / 收起到托盘 / 设置… / 退出**（桌宠和信息条上都可用） |
| 托盘图标 | 菜单：**显示桌宠 / 收起到托盘（跟着当前显隐换字）、用量面板…、设置…、退出**；**左键单击 = 开关**（收着就放出来，放着就收回去）。「收起」走 `win.hide()` 而不是 `win.minimize()` —— 桌宠是无边框透明窗，最小化会在任务栏留一个空图标，而它本来就常驻托盘 |
| 底部信息条 | 常驻显示你勾选的字段（默认：今日已用 / 上下文 / WB 今日 / 缓存命中 / DSH 今日）；鼠标悬停显示完整明细；**高度随内容自动增减**（窗口底边不动、顶边向上长）；45 秒无账自动淡出；**一个字段都没勾时整条收起**（不然鱼脚下会留一个空心的圆角框，看着像界面坏了，还照占高度挡桌面点击） |
| 设置窗口 | 外观（大小 / 形象 / 置顶 / **开机自启**）、**动作（按「什么时候播」分组，可增删排 + 试演）**、自选信息条字段与顺序、插件安装与卸载、关于 |
| 模型扣费 | 每笔调用按金额轻重分档，播「扣费反应」名单里对应那一档的动作 |

上面这些「播什么」全都可以在设置里换 —— 表里写的是默认搭配，见下一节。

窗口透明、无边框、默认置顶、不占任务栏；位置和大小记忆在 `config.json`。

## 动作 × 时机（什么时候播哪个，可以自己排）

上面的反应来自两张表：**有哪些动作**（`main.js` 顶部的 `ACTIONS`）和**什么时候会播**
（`shared/triggers.js` 的 `TRIGGERS`）。中间用一份份**名单**连起来 —— 设置窗口的动作页
就是这五张卡片，每张卡片里放谁，谁就在那个时机播：

| 时机 | 默认名单 | 名单性质 |
|---|---|---|
| 待机随机 | 歪头放电 / 原地晃晃 / 打起精神 | 池子，按 `weight` 加权随机 |
| 偶尔眨眼 | 眨眼 | 池子，自有节拍（两三秒一次） |
| 单击摸摸 | 轻痛 / 普通痛 | 池子，随机挑一个 |
| 双击 | 开心（双击） | 池子，随机挑一个 |
| **扣费反应** | 轻痛 / 普通痛 / 暴击 | **有序**：1 = 最轻的档，往下越来越重 |

| 动作 | 默认时机 | 说明 |
|---|---|---|
| 眨眼 | 偶尔眨眼 | 保持当前姿势，睁 → 闭 → 睁 |
| 歪头放电 | 待机随机 | 歪一下头再回正 |
| 原地晃晃 | 待机随机 | 稳稳地晃两下再归位（幅度比待机呼吸大） |
| 打起精神 | 待机随机 | 从没精神一路亮起来 |
| 开心（双击） | 双击 | 蹲 → 蹦起来眨个左眼 → 落地 |
| 轻痛 / 普通痛 / 暴击 | 扣费反应 | 按金额轻重分级；最重那一档的末帧会定住一张「连续受击」 |

待机呼吸是底子，一直在，不在名单之列。

**「一个动作不在任何名单里」就是关它。** 以前每个动作另有一个开/关，现在没有第二个开关 ——
两套状态迟早打架（关掉了却还在名单里 / 开着却没人播）。设置页底下会列出「没安排时机」的动作，
把它们加进任一卡片就会开始播。

**同一个动作可以同时挂在几个时机上。** 默认的「轻痛 / 普通痛」就是：这一版形象没有专门的
「被摸」素材，所以单击摸摸借的是扣费反应里最轻的两档。卡片的「×」只把它从**这一张**卡片里拿掉，
别处不受影响。

**受击档位和动作名是两回事。** 金额算出来的只有轻重三档（`weak` / `normal` / `critical`，见
`usage.js` 的 `TIERS`），渲染端拿这个档位去「扣费反应」名单里取第 N 个动作。所以「多大的账播哪一段」
是你在设置里排的，不是代码里写死的；名单短了（比如只留一个）就都用那一个，删掉「暴击」不会让
大额扣费变成没反应。插件的 `meta.damage` 里写的就是档位名，老写法（`pain-weak` / `pain-normal`）也认。

**`ACTIONS` 这张表还是唯一真源**：`frameGroups()` 照它扫帧、设置窗口照它画「可添加的动作」、
渲染端照它建片段。加一个动作 = 在 `assets/<形象>/frames/` 里放好帧 + 往 `ACTIONS` 加一行
（顺手写一句 `slot`，它就会默认出现在对的时机里）。渲染端**不认识任何具体动作名字**，也不认识
时机之外的任何东西 —— 所以改搭配、加动作都不用动 `renderer/pet.js`。

名单存在 `config.json` 的 `triggers` 里，**只记和默认不一样的那份**（一样就存 `null`，
以后调默认值时才不会被一堆历史记录压住）。老的 `actions: { id: false }` 配置在读取时自动换算一次，
换算完那一栏就删了。

## 拖动实现（重要）

窗口移动由**主进程**按固定节拍读光标并 `setPosition` 完成，渲染端只在按下/松开各发一次 IPC——移动期间渲染端零 IPC，不会出现「窗口移动比画面提交还快」导致的错位。

实测（`tools\drag-verify.py`，真实鼠标事件 + 逐帧抓屏）：光标移动 216 / -72 px 时窗口位移 **216 / -72**，完全 1:1；拖动全程窗口尺寸恒为 570×630，无漂移。

另一种模式是 CSS `-webkit-app-region: drag`（把移动交给系统），但它在 Windows 上会把这整块区域变成非客户区，网页层收不到鼠标事件，单击/双击/右键菜单都会失效；本项目实测它也并不可靠，因此只作为备选保留。

| 环境变量 | 作用 |
|---|---|
| `WHALEPET_POLL_MS=8` | 调整移动节拍（默认 16ms） |
| `WHALEPET_DRAG_MODE=system` | 换成系统级拖动（`-webkit-app-region: drag`），仅作备选 |
| `WHALEPET_DRAG_POSE=1` | 拖起来时切「拎起帧」。默认关闭：旧形象那张拎起素材是双手前伸的俯视姿势，在桌宠尺寸下会被看成两个头；新形象暂无该素材，开了也是空转 |
| `WHALEPET_SANDBOX=1` | 保留 Chromium 沙箱（默认关闭，见下） |
| `WHALEPET_GPU=1` | 保留硬件加速（默认关闭，见下） |
| `WHALEPET_REPORT=1` | 启动自检：把启动路径、窗口句柄、GPU 状态、渲染端报错写到 `tools/startup-report.json` |
| `WHALEPET_CAPTURE=1` | 截图验证：把**窗口自身**的像素存到 `tools\capture-*.png`（走 `capturePage`，不受 DPI 缩放影响） |
| `WHALEPET_CAPTURE_MS=4000,8000` | 配 `WHALEPET_CAPTURE` 用，did-finish-load 后第 N 毫秒各抓一帧 |

> 用量监控相关（`WHALEPET_USAGE` / `WHALEPET_USAGE_MS` / `WHALEPET_CTX_LIMIT` / `WHALEPET_NO_BALANCE` / `WHALEPET_FAKE_HIT` / `WHALEPET_FAKE_BURST` / `WHALEPET_FAKE_HIT_AT` / `WHALEPET_FAKE_LEVEL` / `WHALEPET_OPEN_SETTINGS`）见下面「用量监控」章节。

### 沙箱与硬件加速（默认都关掉）

这台机器上 Chromium 的渲染沙箱会和宿主环境冲突，表现为 **GPU 进程反复崩溃、Electron 紧接着 FATAL 退出**——现象就是「双击了但什么都没发生」；即使侥幸起来，窗口也是白的。实测结论：

| 沙箱 | 硬件加速 | 结果 |
|---|---|---|
| 开 | 开 | FATAL，进程直接退出 |
| 关 | 开 | 进程活着、页面加载成功，但窗口不显示 |
| 关 | 关 | **正常显示**（当前默认） |

所以 `main.js` 在启动最早期就关掉沙箱并禁用硬件加速。本桌宠只加载本地素材、不访问任何网络页面，关掉沙箱的暴露面很小。如果你的机器显卡正常、想换回默认：设 `WHALEPET_SANDBOX=1 WHALEPET_GPU=1` 再启动。

### 素材说明

`assets/shayu/`（「傻鱼」形象）只有四张 AI 原画，整套 **58 帧全部是程序化合成**的，分两步：

| 脚本 | 干什么 |
|---|---|
| `tools/make-shayu-sticker.py` | 原画 → 透明贴纸（去文字 → 去白边 → 清碎片） |
| `tools/make-shayu-frames.py` | 贴纸 → `frames/` 下的各段动作帧 + `states/` + 托盘图标 `idle.png` |

两个脚本都认环境变量 `WHALEPET_ROOT`：默认写本仓库的 `assets/shayu/`，设了就往那个目录写 ——「先在临时目录里跑一遍、看一眼再落盘」用得上（别拿正式素材当试验田）。

四张原画是：**双手叉腰**（全身站姿，**所有动作的主体模板**）、**双眼睁开**（剪刀手，半身）、双眼闭合、眯眼 wink（最早那张）。

> 分工：**身体一律用叉腰那张**；「睁眼」那张提供眼睛的**位置基准**，「闭眼」提供**闭眼那块像素**（眨眼和「开心（双击）」的那一下眨眼都用它）；「眯眼」那张**一格像素都不进合成** —— 它是另一套构图，搬进来就会在叉腰的剪影里叠出第二套描边（见下面第六条）。PNG 还留在 `assets/shayu/` 里，但生成器不读它。

抠图三步：

1. **删字**：按颜色判别贴纸上的文字笔画，再沿笔画量出的下沿做**镜像反射**补回被字挡住的裙摆。这里不能用 inpainting —— 荷叶边是周期性的弧，`INPAINT_TELEA` 会拉出一长条灰白渐变把它抹平。
2. **去白边**：轮廓外本来就画了一圈白描边，缩到桌宠尺寸后是整圈扎眼的光晕。判据要**三条同时成立**：亮度高于墨线阈值才算「可通行」→ 从画面四边洪泛（墨线挡路，进不去角色内部）→ 再限定「离已透明像素不超过 N px」。只用前两条会把**女仆围裙**整片吃掉，只用第三条会把**头饰**外沿削掉。
   AI 重绘的那几张背景不是纯白（落在 247~253），所以判据是「**近白且低饱和**」（`min≥230 且 max-min≤20`），不是早先那个写死的 `|rgb−253|≤2` —— 后者在 `_source-shut.png` 上会把 98.9% 的画面判成前景。
3. **清孤立碎片**：按「只留最大连通分量」处理最稳。

合成帧现在有七条设计（都写在 `make-shayu-frames.py`头部注释里）：

- **主体统一用「叉腰」那张。** 另外三张是**半身构图**：源图里裙摆画到画面下边界就被切了。而叉腰是完整站姿 —— 裙子有完整蕾丝下摆、还有一条**带尾鳍的完整鲸尾**。所以直接把它当模板，四个姿势的结构天然一致，不用再拼贴。
- **「半身」= 抹掉腿，不是裁到裙摆。** 叉腰剪影里最低的那条是**腿**（`x 244..424`、`y≥802`），半身像不要腿；但它自己的**尾巴**（`x>430`）一直垂到 `y≈824` —— 按矩形裁到裙摆下沿（795/800）会把尾鳍连着一起切掉。所以改用掩码：只把腿那一片抹透明（`LEG_X0..LEG_X1`），其余全留。裙子收在完整的蕾丝波浪上，尾巴也完整。
  
  这一片**不是一条直线**：蕾丝下沿是波浪形的，波谷处大腿根会从蕾丝缝里露出来（用户报的「裙子下面还能看到一点腿」），而波峰处蕾丝本身就低到直线以下，整条抬上去又会把蕾丝啃掉一口。现在的做法是**逐列切**：判据是「大腿根的暖粉」（`R-G ≥ 20` 且 `R-B ≥ 8`）——蕾丝褶皱只有 `R-G 12~18 / R-B ≈ 0`、够不到；裙子上那几颗金色星星 `R-B` 上百、被第二个条件挡住。每列从上往下找到第一个暖粉像素就在它上面一行切，没找到的列沿用 `LEG_TOP`。实测只有 **56 列**被抬高、切线在 792~802 之间波动，正好落在花边波谷里；`content_bottom()` 没变（最低的仍是尾巴），所以挤压锚点不受影响。对照图见 `tools/legs-fix.png`。
- **表情逐只眼搬，锚点用瞳孔自动定标。** 两张脸的**眼距**不一样（open 141px、叉腰 133px），所以必须逐只眼搬。但锚点**不能目测** —— 早先手标的中心差十几像素，表现就是「闭眼顶到刘海 + 下面残留一道睁眼睫毛」，而手写的缩放 `1.02` 方向还是反的（实际要缩小到 **0.938**）。现在改成**用瞳孔定标**：瞳孔是虹膜正中、全图最暗、形状最稳的特征，左右各找一个，两点就定死了位移和缩放（`calibrate_eyes()`，跑起来会把实测值打出来）。
- **眨眼只留「睁 → 闭 → 睁」三段硬切。** 中间那帧试过两种做法都不行：`open*0.45 + shut*0.55` 会把睁眼的虹膜和闭眼的睫毛线**叠成重影**（就是「脸上一堆意义不明的线」）；「眼皮下落」又因为闭眼的睫毛线本来就画在眼睛偏下、压不到一半，看着和全闭没区别。
- **抹掉抠图漏下来的「封闭白块」。** 抠图只从画布四边洪泛判背景，**被角色轮廓包住的背景**（尾巴根部那块、头发缝里几块）洪泛进不去，就留成了不透明近白 —— 桌面上是「尾巴上方一块白」，压深色壁纸特别突兀。既然用户说「直接透明无遮挡即可」，就在公共空间里按「近白 + 不透明 + 成块 + 不在保留区」抹掉（`HOLE_KEEP` 保护荷叶边 / 围裙 / 裙摆蕾丝 / 眼白）。
- **整张脸重画成「只有头发 + 眼睛 + 一对眉毛 + 嘴巴」。** 之前是逐个点位去补脸上的异物（额头亮点、眉心竖线、脸颊细道、腮红杂点、被搬运错位的眉毛），补不完 —— 改成整张脸统一处理（`clean_face()`）：以两眼瞳孔为心画一个**椭圆脸区**（`rx=0.80d`、`ry=1.05d`、心下移 `0.34d`；更大就会把脖子肩膀一起圈进来），脸里只认**四样**要保留的东西，其余全部填成同一片皮肤。三处关键细节：
  - **肤色基线 `SKIN_REF` 只测一次**（用主体帧那块脸最干净的），之后所有表情帧复用。逐帧各测会漂：闭眼帧的眼窝填充占掉了鼻子采样点，退回全脸取中位数时又混进眼白残留，基色从 `[250,228,219]` 掉到 `[241,214,206]` —— 桌面上就是「眨眼时脸忽然暗一档」。
  - **眉毛用「比周围皮肤暗」认，不用绝对色。** 眉毛只有 1~2px 宽又是抗锯齿画的，纯色像素极少：按绝对色（暖 + 中暗）筛，窗口里 1478 个候选只落中 **16px**，眉毛几乎被自己抹平。改成拿亮度度的 12px 高斯模糊当「这里本该多亮」，比它暗 26 以上就是眉毛，右窗口命中 1114px。
  - **脸里任何近白色一律平涂**（判据是「到 `SKIN_REF` 的距离 < 30 且低饱和」）。三类白都要清：荷叶边蹭进脸区的白边、抗锯齿过渡色 `[247,235,231]`、以及闭眼帧 `build_closed_eyes()` 用 `skin_fill()` 填眼窝时从旁边眼白插值进来的 `[255,250,244]`（桌面上是脸颊一片死白）。
- **「开心（双击）」的滞空帧：一格「眯眼」像素都不用。** 蹦起来那一帧的身体和脸与其它帧**逐像素同源**，只有角色左眼闭着（用 shut 那张的闭眼贴法，`build_closed_eyes(C, half="R")`）。为什么不整张搬「眯眼」原画、也不嫁接它的比耶左臂：见「动作质量」第一条。
- **闭眼：眼窝只盖瞳孔周围那一圈，残迹单独清。** 贴闭眼之前要先把原画睁眼那块抹成皮肤，而「抹多大」是个坑：
  - 抹小了（`rx=0.31·眼距 / ry=0.24·眼距`，比瞳孔大一圈）：原画的**上睫毛线和眼睑残迹**留在蒙版外面，和新贴的闭眼叠成两道线（用户报的「左眼上杂乱线条」）；
  - 抹大了（试过 `0.46 / 0.34` 并把中心上移 `0.10·眼距`）：残迹是没了，但**蒙版盖到哪里、那里贴的就是「闭眼那张素材自己的脸」**—— 它是另一次生成的画，皮肤比叉腰这张白，于是整个眼睑变成一块发白的平板，桌面上就是「眨眼时原本的位置变成白色」。
  
  所以现在**退回小眼窝**（底色与眼睑明暗都来自原画），残迹改用 `tidy_eye()` 单独清：瞳孔附近的小椭圆里，「比 9px 局部亮度差 22 以上」的像素按连通块分组，**只留最大的那一块**（闭眼睫毛线），其余小块按行插值填成皮肤。实测一次清掉 78 px / 6 块（左眼 12 px），顺手把素材自身搬过来的**高光点**（白斑）也一起清了；眉毛窗口整个排除，不碰正经五官。同样**只影响 `blink-02` 与 `happy-03` 两帧**，对照见 `tools/eye-fix.png`。
  
  > **回退记录（第五轮口径）**：中间试过一版「分层椭圆」的清法 —— 候选在外圈找、只保留内圈那一块，
  > 确实把眼睑上方那几笔碎线清干净了，但**要替换的面积太大**（每只眼 2600~3100 px），
  > 眼睑被行插值填成一块平滑的「喷枪」色，反而丢了原画的皮肤明暗。已按用户要求换回现在这版：
  > 皮肤是原画自己的，代价是素材自带的那几笔浅色碎线还留着一点。想再试分层那版，
  > `whalepet-fix/backup/make-shayu-frames.pre-revert5.py` 就是它。


还有一条老规矩：**底边锚定做挤压，锚点用主体自己的下沿**，否则「蹲下」看起来像整体缩小。

改完素材**两个脚本按顺序重跑一遍**（贴纸 → 帧）。帧生成器末尾会打印裁切自检，有内容贴到画布边缘会点名；同时出一张接触印相表 `tools/_qa-frames.png`，一屏看完所有动作。

## 界面

配色全部取自傻鱼本体：藏青（头发 / 裙）、藕荷蓝（蝴蝶结）、冰白（围裙）、金（腰饰）。

**桌宠信息条**是**冰白底 + 藏青字**，不是深色。这是刻意的取舍：桌宠常驻桌面，深底在浅色壁纸上会糊成一块，冰白底配藏青反而哪个壁纸都读得清，也和它身上的围裙是一族。

**设置窗口**是一块浅色的卡片式界面（比它那条信息条亮一档）：左边一列藕荷蓝的导航栏，右边是当前那一页的内容。导航五项 —— 外观、桌宠上显示、动作、数据源插件、关于，`data-page` 和 `id="page-…"` 一一对上，**点谁看谁**。

原来是「一页往下滚」，五段挤在同一个滚动条里：想改「动作」得先滚过整个字段列表，而五段里通常只有一段是你现在要看的。拆成页之后这个代价就没了。**每页的计数徽标挂在导航项上**（`5 项` / `8/8` / `6/6`）—— 一栏扫下去就知道每页现在什么状态，不用逐页翻；这也顺手解释了为什么 `#field-count` / `#action-count` / `#plugin-count` 这三个 id 在 `settings/index.html` 里跑到了 `<aside>` 里而不是各页标题中（渲染端那三处赋值一行都不用改）。左右留白保持 **12px** —— 再宽，卡片两侧会空出一大条白，内容显得「缩在中间」；窗口宽度则从 580 放到 **700**，多出来的 120 正好是导航栏的宽度，内容区宽度没被挤掉。

翻页会用 `localStorage` 记住（key `whalepet.settings.page`），下次打开还在这一页 —— 设置窗口是常开常关的，每次弹回第一页很烦。存在渲染端而不是 `config.json`：这是「窗口自己记着的状态」，不是用户的配置。

信息条和设置里的预览是**同一份**，抽在 `shared/`：

| 文件 | 作用 |
|---|---|
| `shared/pills.css` | `.pillbar`（条容器）+ `.pill` / `.lb` / `.nm` / `.un`（单位小字）+ 语义色（`.t-peak` / `.t-valley` / `.t-warn` / `.t-danger` / `.t-off`） |
| `shared/pills.js` | `Pills.render(box, fields)` / `Pills.empty` / `Pills.key` |
| `shared/hitpacing.js` | `HitPacing.createPacer({gap, now, setTimer, hasPending, onEmit})` —— 飘字的出场节拍（纯时间逻辑，可用假时钟测） |
| `shared/triggers.js` | 时机表（`TRIGGERS`）+ 名单运算：默认名单 / 收拾配置 / 增删排 / 统计（纯数据，node 直接 require 来测） |
| `shared/petsize.js` | `baseSize(scale, barH)` / `petAreaH()` / `maxScale()` / `clampScale()` —— 尺寸几何与倍数上限（纯几何，见「尺寸」一节） |
| `shared/cachehit.js` | `CacheHit.split / rate / text / tone / detail` —— 缓存命中率的口径归一（三种 mode，插件和面板跑同一份，见「字段」一节） |

字段的形态是 `{ id, label?, value, unit?, tone?, title? }`：`unit` 会渲染成数字后面的小字（`5.47 积分` / `132.5万 token`），字号更小、颜色更淡 —— 读数字时它不抢眼，需要的时候又在那儿。

两个窗口各写一份 CSS 迟早会漂移（改了颜色只改一处），所以两边 `<link>` / `<script>` 同一个文件。**注意 `pills.css` 要排在 `pet.css` 之前**，让 `pet.css` 能用 id 选择器盖掉「位置」和「存在感」（透明度、hover、pulse）那几行 —— 外观归 shared，位置归自己。

`#usage` 元素本身就带 `.pillbar` 类，没有内层包裹元素；渲染端量到的 `getBoundingClientRect()` 直接就是那条的高度。

## 设置窗口

右键桌宠或信息条 →「设置…」（托盘菜单里也有）。菜单本身只有三项，功能全在这里 —— 左边一栏一项，一项一页：

| 导航项 | 内容 |
|---|---|
| **外观** | 大小（小 70% / 中 90% / 大 110%，**默认小**）、形象（`assets/` 下每套一个）、窗口置顶 |
| **桌宠上显示** | 实时预览 + 字段行（`↑ ↓ ×` 排序/移除）+「可添加的字段」胶囊 |
| **动作** | 按「什么时候播」分五张卡片（待机随机 / 偶尔眨眼 / 单击摸摸 / 双击 / 扣费反应）。卡片里是该时机的动作胶囊：点名字 = 试演，点 `×` = 从这一张卡片里拿掉；右边「＋ 加动作」加进来。扣费反应是有序的，胶囊带序号和 `↑ ↓`（1 = 最轻的档）。页底列出「没安排时机」的动作 |
| **数据源插件** | 每个来源一张卡片：安装 / 卸载、状态、读取路径、用户插件可删除文件；本页右上角还有「插件目录」「重载插件」 |
| **关于** | 版本、交互说明、数据源清单（含每家的读取路径）、配置文件位置 |

加一页要动的地方只有两处：`settings/index.html` 里加一个 `<section class="page" id="page-x">` 和一个 `<button class="nav-item" data-page="x">`，`settings.js` 的 `PAGES` 数组里加一个字符串。页的显隐、导航高亮、滚动归零都是 `showPage()` 统一管的，不需要各写一遍。

**改大小不会让桌宠跳动**：`setScale()` 保持**底边不动**、把顶边往上推（和「信息条长高」是同一套做法）；反过来直接改 `height` 会让窗口往下长，桌宠本体跟着掉一截。

**开机自启是「登录时启动」项，不是后台服务。** 走 Electron 的 `app.setLoginItemSettings()`（Windows 上就是注册表 Run 键），不装服务、不要管理员权限 —— 好处是你能在「任务管理器 → 启动」里亲眼看到它、随时关掉。一个桌宠不该往系统里藏东西。两条实现细节：

- **开发态必须把应用目录当参数带上**：`electron .` 的 `process.execPath` 是 `electron.exe` 本身，不传 `args: [__dirname]` 的话开机只会拉起一个空壳，桌宠反而不出来。打包之后才不用传。
- **配置是唯一真相**：启动时拿 `getLoginItemSettings()` 和 `config.json` 对一次，不一致就以配置为准重新写一遍 —— 你在「启动应用」里手工删掉条目之后，下次开桌宠会自动补回来，而不是「开关明明是开的、开机却没反应」。

**「收起到托盘」走 `hide()` 而不是 `minimize()`。** 桌宠是无边框透明窗，最小化会在任务栏留一个空图标；而它本来就常驻托盘（图标 + 菜单），所以直接隐藏、留托盘当入口。托盘菜单第一项跟着显隐换字（「收起到托盘」↔「显示桌宠」），左键单击就是开关。

**卸载的语义是「不装载它」**：不读它的日志、不占内存、它声明的字段自动从信息条上摘掉。文件不动 —— 内置插件本来就该随时装回来。用户级插件额外有「删除文件」，那才是真的删。手滑卸载了也不用慌：重新安装后字段会回到「可添加的字段」里，但**不会**自作主张塞回信息条（否则排好的顺序会被悄悄改掉）。

### 尺寸：「大」为什么从 140% 改成 110%

形象是**只缩不放**的 —— `#pet` 用 `max-height` / `max-width` 做 contain（见 `renderer/pet.css`），图片永远长不过自己的原始像素（帧画布 420×462）。于是倍数大到某个程度之后，形象已经画满原始像素、不再变大，窗口和信息条却还在按倍数长 —— 「大 140%」正好落在那里。`tools/probe-scale.py` 起真窗口、逐档抓图、量鱼身的实际包围盒（CSS px）：

| 档位 | 窗口 | 鱼身 | 占窗口宽 | 鱼底到信息条 |
|---|---|---|---|---|
| 中 100%（旧） | 380×472 | 323×321 | 85.1% | 41px |
| 大 140%（旧） | 532×660 | **372×369** | **69.9%** | **171px** |
| 小 70% | 266×342 | 204×229 | 76.7% | 18px |
| 中 90% | 342×440 | 280×313 | 81.9% | 23px |
| 大 110% | 418×514 | 353×396 | 84.5% | 27px |

（后三行是**换主体之后**重量的：信息条高度不完全一致 —— 字段勾得多它会换行变高，窗口也跟着长，所以「鱼底到信息条」这一列只用来比趋势，别当绝对值。另外表里的「鱼身」是**不透明部分**的包围盒，比帧画布窄一圈（画布 420×462，鱼身 354×395）—— 判断「窗口有没有浪费」要看它，而不是看画布。）

旧「大」只比「中」大了 15%（一倍四的倍数全花在窗口上了），桌面上看到的就是「一个很宽的空框里放着鱼，框底吊着一条同样很宽的信息条，中间空出一大截」——「大形象显得太宽」说的是这个，**不是拉伸**：三档鱼身的长宽比实测 1.119 ~ 1.124（差 0.5%），和叉腰那张立绘本身的比例一致，没有任何变形。

现在三档是 **70% / 90% / 110%**，并且倍数有上限：`shared/petsize.js` 的 `clampScale()` 取 `min(MAX_SCALE, maxScale(信息条高度))`。信息条越高、留给形象的高度越少，上限就越低（信息条 52px 时 1.11，320px 时 1.07），所以「大」永远落在「形象还跟着变大」的范围里；老配置里存着的 `1.4` 读进来会被夹到这一档并落盘。`tools/test-scale.js` 守着这条：任何信息条高度 × 任何档位，形象都不许画满原始像素，形象宽还得铺满窗口宽的 80% 以上，相邻两档至少差 20%。

### 主体换成「叉腰」那张：裙子不再断、尾巴不再被切

**裙子被「刀切」是素材的构图问题，不是渲染问题。** 四张贴纸里三张（张嘴 / 闭嘴 / 眨眼）是**半身构图**：源图里裙摆画到画面下边界就断了，抠出来是一条**水平硬切边** —— 而叉腰那张虽然自身是完整站姿，原来的 `crop=795` 又正好裁在蕾丝**上方**，连自己那条也切掉了。于是桌面上**四个姿势的裙子全是断的**。

早先的补法是「把叉腰那条蕾丝剪下来贴到半身素材的下缘」（`LACE_BOX` / `lace_band()` / `add_lace()`）：能救裙子，但救不了别的 —— 那是拼接，接缝处永远差一层。

这一版换了个更彻底的做法：**主体模板直接换成叉腰那张的半身**，四个姿势（睁眼 / 闭眼 / 眯眼 / 叉腰）共用它，后三张只贡献「眼睛那块像素」。结构天然一致，拼贴那套代码整段删掉了。

关键在**「半身」怎么切**：剪影里最低的那条是**腿**（`x 244..424`、`y≥802`），半身像不要腿；但它的**尾巴**（`x>430`）一直垂到 `y≈826`，按矩形裁到裙摆下沿就会把尾鳍切掉一截。所以改用掩码 —— 只把腿那一片抹透明。裙子收在完整的蕾丝波浪上，尾巴也完整。

尾巴这里有个取舍：叉腰那条是**带尾鳍的完整鲸尾**；原「待机主体」那条（`_sticker-open.png`）其实是被原画右边界**切掉一角的深蓝团块**，还和头发糊在一起 —— 所以「查缺补漏」用了叉腰这条完整的。

**尾巴根部那个白块：抠图漏下来的封闭背景。** 抠图的背景判据是「近白且低饱和 + 从画布四边洪泛得到」—— 而**被角色轮廓包住的**背景（尾巴与裙子、头发之间那块，还有头发缝里几小块）洪泛进不去，就被当成前景留成了不透明近白。桌面上就是「尾巴上方糊着一块白」，压深色壁纸特别突兀。修法是在公共空间里按「近白 + 不透明 + 成块 + **不在保留区**」抹透明（`drop_hole_white()` / `HOLE_KEEP`），一次抹掉 25.7k px（四张姿势合计）。

为什么保留区是标定的、不是自动判的：这些白块和合法白色（荷叶边 / 围裙 / 裙摆蕾丝）在颜色上几乎一样（都是暖白，R>G>B）；用「背景渐变模型」也分不开（白块的偏差中位 7.7，裙摆蕾丝 9.8 —— 蕾丝反而更"不像背景"）；「隔一条细墨线」这种几何判据同样不行（荷叶边外侧也只隔一条墨线）。试了三种自动判据都不成立，最后按这个仓库一贯的做法，用一份**标定过的保留区**（和 `REF_HEM` 同一个套路），并出 `tools/_h-keep.png` 核对。

**形象离信息条太远**：帧画布原本 420×480，而形象的最低点落在 y≈437 —— 底下 43 行是纯空白。桌宠常年挂在桌角，这截白边就一路顶到信息条上方。画布收了两轮（480 → 458 → 428），换主体时又长回 **420×462** —— 叉腰那张比 open **又瘦又高**（692×773 vs 757×743），`K` 从 0.49 提到 0.51 才能让它在画布里的占位和原来持平，画布得跟着长。`shared/petsize.js` 的 `CANVAS_H` 必须同步；`PET_AREA_H` 420 → 412 → 385 → 415 是为了把 `maxScale` 顶回 1.1 以上，否则界面上「大」那一档会被 `clampScale` 悄悄夹成 1.09（点了「大」却不是 110%）。`tools/test-scale.js` 拿真 PNG 头核对 `CANVAS_H`，画布改了、常量忘了改会当场红。

**构图也要跟着调**：光收画布不够，还得把形象往上顶（生成脚本的 `OY` 33.3 → **3.3**）—— 不然收掉的那一截会全堆到底部，信息条又被推远。上移后头顶留白从 **16.2% 压到 9.9%**、底部 22 行。半身立绘的惯例是头顶留 8~10%，16% 看着就是「人没填满画面、整体偏下」——「比例不符」的来源不是人物画错了，是**它在画布里的位置不对**。

底部留白占画布高度的比例两版几乎一样（画布从 428 长到 462，留白也从 21 行到 22 行），所以「形象底 → 信息条」这组实测值继续成立（`tools/probe-scale.py`，CSS px）：

| 档位 | 改前（420×480） | 现在（420×462） |
|---|---|---|
| 小 70% | 28 | **18** |
| 中 90% | 37 | **23** |
| 大 110% | 46 | **27** |

（这里的「改前」是画布还是 480 的那一版 —— 改前的数按同一信息条高度反推：画布留白从 43 行收到 22 行，少了约一半。）

> 调试这类素材问题，**最快的办法是把中间产物 dump 出来看**：把掩码叠在源图上、或者把待贴的那块单独裁出来放大，一眼就能看出「切到腿了没有 / 尾巴还在不在」。在成品帧上量像素反而会被误导 —— 那些像素已经和裙摆、头发混在一起了。

### 动作质量：黑边、眨眼糊，以及切换的「僵」

桌面上能一眼看出来的三个问题，根子都在**两张素材没对齐**上。

**① 双击跳跃时脸会「变形」，跳起来身上还有一圈对不上的线。** 这两件事同一个根：滞空帧搬了**另一套构图的整张原画**（`_sticker.png`「眯眼·剪刀手」，712×702，跟张嘴/闭嘴那两张的 760×749 不是一套）。

`build_expression()` 圈眼区用的是 `eye_weight()` —— 它算的是**两张图的差异**。对「同一姿势的睁眼 / 闭眼」成立（差异只出现在眼睛），对**两张不同的画**就不成立：头发走向、荷叶边弧形、蕾丝细节处处都不同，差异图整片饱和。实测把 `eye_weight(open, wink)` 映到 hips 上，`m>0.10` 覆盖了 **53.5% 的身体**（`m>0.60` 也有 31.7%）。于是 `rgb = hips*(1-m) + wink*m` 等于**把 wink 那张在 hips 的剪影里又铺了一遍**：

- 脸上是**两张脸**按对半叠着（量一下：最终像素里「与 hips 一致」的只剩 **50.9%**）—— 桌面上就是「双击蹦起来时脸变形了」；
- wink 自己的**描边、荷叶边、裙摆蕾丝**落在 hips 轮廓里侧，成了一圈偏移的线 —— 桌面上就是「跳跃时背后有残影」；
- 更隐蔽的一刀：`clean_face()` 当时是「谁采到 300 个采样点谁就就地更新 `SKIN_REF`」，这张混合脸被量成`[245,203,190]`（混进了 wink 的腮红）并写进**全局**基准 —— **之后每一张脸**都跟着偏红。

中间还试过「只把 wink 的比耶左臂嫁接过来」：也不行。那个窗口里**大部分像素不是手** —— 掩码内 19238 px 只有 **11.4% 是肤色**、24.0% 是深蓝（头发/袖口），wink 的头发、荷叶边、袖口一起搬了过来，手周围照样是一圈对不上的描边（同一张脸上「残影」的缩小版）。

最后一刀是**不用它**：滞空帧改成「叉腰主体 + 只闭角色左眼」，闭眼那块像素走 blink 用的同一套 `build_closed_eyes()`（加 `half="R"` 只闭画面右眼 = 角色的左眼）。三个配套改动：

1. `POSES` 里删掉 `wink`，连同只为它服务的 `align_wink_to_hips()` / `frill_box()` / `graft_arm()` / `ARM_BOX` 一起删 —— 留着只会让下一个人以为它还能用；
2. `build_expression()` 补一道**几何闸门** `eye_gate()`：差异图只在两眼椭圆里算数。哪怕以后又有人把另一套构图的画塞进来，最坏也只是眼睛那块脏，不会再把整只替换掉；
3. `clean_face(..., calibrate_skin=True)`：肤色基准**只由主体帧标定**，表情帧不再改它。

修完，滞空帧与待机中立帧的差异从 **29249 px 降到 1754 px**（差异 >40 的像素），而且剩下的全部落在**闭着的左眼**上 —— 也就是说，跳起来那一帧和别的帧是同一张画。生成器同时会打印每一步用的肤色基准：改前 wink 那一步是 `[245,203,190]`，现在三步都是 `[250,228,219]`。

代价是**没有「左手比耶」了**。那个手势只存在于另一套构图的画里：要么接受一圈残影，要么不要它。真想要比耶，得**另画一张「蹦起来比耶」的立绘**（和叉腰同一套构图）再让生成器用它 —— 而不是从别的画上剪一块下来贴。

**② 眨眼时脸上有多余线条（用户点名过）。** 半闭帧原本是「睁眼 × 45% + 闭眼 × 55%」**交叉混合**出来的 —— 睁眼的**虹膜**和闭眼的**睫毛线**叠在一起，桌面上就是一张脸上印着好几道**看不出是什么的线**。中途试过改成「眼皮下落」（把闭眼那张的睫毛线以上盖过来），但闭眼的睫毛线本来就画在眼睛偏下的位置，压下来也压不到一半，看着和全闭没区别、白多一帧。最后一刀：**把中间帧整段砍掉** —— 睁 → 闭 → 睁 三段硬切（2D 动画里的眨眼本来就是硬切），靠 `ms: [56, 140, 56]` 让「闭」这一帧停久一点，全程 252ms。

另外差异蒙版只在**两边都不透明**的像素上算（轮廓边缘的 alpha 是渐变的，两张素材在那儿天然差几像素，算进去会让蒙版沿着描边糊一整圈）。

**②b 眨眼的位置和比例也得对（用户也点名过）。** 闭眼那块像素是从「睁眼」那张算出来、再搬过去的，锚点写错就会「闭眼顶到刘海 + 下面残留一道睁眼睫毛」—— 看上去和乱线是同一类毛病。锚点最早是拿网格图**目测**的（两个中心各差十几像素），缩放还手写成了 `1.02`（**方向反了**，实际要 **0.938**）。现在改成**瞳孔自动定标**：瞳孔是虹膜正中、全图最暗、形状最稳的特征，左右各找一个，两点就定死了位移和缩放。生成器每次会打印实测值（`眼睛定标：瞳孔 open (351.0,497.4)/(490.8,476.8) → hips (335.8,472.8)/(467.3,456.2)  眼距 141.3 → 132.6  EYE_K=0.9381`），换了素材就能立刻看出标定有没有崩。找不到成对瞳孔时**回落到常量并告警**，不会静默贴歪。

**②c 闭眼那块像素是另一张画上的，皮肤不一样。** 位置对了之后还剩一个毛病：源图（闭眼那张）眼睛周围的**皮肤和红晕**跟目标脸并不相同，直接按蒙版混过去，桌面上就是「眼周一块发灰的补丁 + 一条细弧」—— 用户第二次报的「脸崩了」就是它。三处一起改：

1. **色调整平**：拿蒙版边缘那圈**仍然算皮肤的像素**（亮度 >185，把已经浸到刘海上的部分排除掉）求出每个通道的比值，把源图整体拉平再混。
2. **睫毛线单独再印一遍**：混完线条会变淡，闭眼就看不清了；印的时候按亮度做软过渡，不要硬阈值（硬阈值会断成虚线）。
3. **蒙版别贪大**：`eye_weight()` 的差异图模糊过，边缘会浸到刘海上，早先"把眼区填成皮肤再画线"的做法就是在这里糊出一条灰带 —— 所以最终没走"填皮肤"那条路，而是"色调对齐后再混 + 复印线条"。

**③ 切换动作的僵硬感。** 素材层面可以量化：每个动作的首/末帧与待机「中立帧」差多少（差异 >50 的像素占比）。改前 `hips` 首 **54.5%** / 末 **57.4%** —— 待机主体是「比耶站姿」、叉腰素材是另一套姿态，从待机切过去等于一瞬间换手（当时在首尾各包一帧 open 中立姿态来抹平，那是绕过问题）。现在**所有动作共用同一个主体**，首尾帧本来就是同一姿态，「跳」从根上没有了 —— 唯一曾经例外的是「开心（双击）」的滞空帧（它当时整张换成了另一套构图的画）；现在那一帧也回到同一张画上了，只多一只闭着的左眼（见第一条）。`happy` 的起势帧仍保留（不然双击瞬间直接塌下去）。渲染层面：`playClip` 切片段时给一次 **90ms 交叉淡出**，但**逐帧推进不加** —— 否则每秒六次淡入反而在抖。

**这里的坑是「拿哪一层淡」**（用户报的「眨眼/打起精神会闪一下」）。上一版的写法是**同一张 `<img>` 上 `opacity: 0.45 → 1`**：窗口本身是透明的，
透明度一低就是**整只鱼半透明**、桌面背景直接透上来 —— 桌面上看就是「闪一下」。而眨眼和「打起精神」都是**进一个片段、出一个片段**，
各淡一次，所以这两个动作最明显。现在改成**两层交叉淡出**：`#pet`（当前帧，永远不透明，接鼠标事件）在上，`#pet-prev`（上一帧，只在 90ms 里从 1 淡到 0，`pointer-events: none`）在下。
任何一帧的合成都不会出现半透明的那一瞬；顺带还盖住了「新帧没解码完先画一帧空白」—— 预加载那边也补了 `img.decode()`（只 `new Image()` 不保证解码）。

实测（真机抓帧，60ms 间隔共 25 帧、跨越多次片段切换）：不透明像素数稳定在 **10.4~10.9 万**、最大 alpha **恒为 255** —— 没有一帧是「整只鱼半透明」。
（`playClip` 抓旧 src → 交给 `#pet-prev` → 再给 `#pet` 换新帧，顺序反了就只剩两帧相同。）

`revive` 首帧仍差 76.7%、`critical` 首帧差 39.8%，**是刻意留的**：前者要「突然蔫掉」的落差，后者要让扣费到达后 260ms 内就有变化（否则抓帧看起来像"根本没播"）。

帧数随之变化：`blink` **4 → 3**（砍掉糊脸的半闭帧）、`hips` **10 → 8**（主体本来就是叉腰，原来的起势/收势两帧反倒成了「换姿势」）、`happy` 4→5、`revive` 7→8，整套 **57 → 58 帧**。注意 `ACTIONS` 里 `frames: ['blink', 3]` 的第二个数是**帧数硬上限**（`scanActions` 按它拼文件名），帧数改了忘同步，新帧根本不会被加载 —— 这是静默失败，桌面上只表现为「动作少了一截」。生成脚本的 `prune()` 会按本轮产出删掉上一版的旧帧，防止目录里留死文件。

**缓存命中率每个来源都有一份**，口径统一为 `命中 / (命中 + 未命中)`，但**各来源账本里字段的含义是三套不同的东西**，归一化在各自插件里做（`shared/cachehit.js` 的三个 mode）：

| 来源 | mode | 为什么 |
|---|---|---|
| WorkBuddy | `pair` | 账本里 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` 是两个独立字段 |
| DSH | `aside` | `inputTokens` 是**未缓存**那部分（按 input 价计费，拿 `costInput`/`costCache` 对得上），`cacheReadTokens` 单列 |
| Claude | `aside` | Anthropic 的 `usage.input_tokens` 不含 `cache_read_input_tokens`（官方口径），两边不相交 |
| Codex | `subset` | OpenAI 口径的 `cached_input_tokens` 是 `input_tokens` 的**子集**，必须相减 |
| ZCode | `subset` | 它把 Anthropic 的 `input_tokens` 和 `cache_read_input_tokens` **合并**成了 `inputTokens`（实测 128/128 条） |

最阴的一处：**DSH 和 ZCode 的字段名一模一样**（都叫 `cacheReadTokens`）而口径相反 —— 同一条记录按 `aside` 算出 46.7%、按 `subset` 算出 87.7%，差一倍。所以口径是按实测结论写死的，`tools/test-cache-hit.js` 里逐条钉住。

**「今日已用」是核心字段，不依赖任何插件**：它只读各插件 `raw()` 里的 `todayTokens` / `todayCredit`，所以以后再装一个插件，它自动就出现在这个合计里，不需要改 `usage.js`。单位不同就不换算 —— 只有 token 就只显示 token，只有积分就只显示积分，两者都有就并排。

> 信息条上**没有**「今日扣了多少」这一格，这是刻意的：**一笔一笔的金额是流水，不是指标**，
> 它以飘在鱼身上的 `-多少` 呈现（见「每笔账的『-多少』」一节）；要长期读数就用上面表里的「今日已用」。

顺序就是你排的顺序。用量面板里那个「信息条预览」按**当前配置的顺序**画，但每个字段的文字和颜色仍然是主进程算好的那一份 —— 顺序是本地的、格式是主进程的，各管各的。这样「刚点完 ↑」预览会立刻跟上（不会等下一轮 2.5s 轮询，看着像点了没反应），而数字永远和桌宠上那条一致。

每笔用量到账，主进程按这笔账的金额定一个**档位**（`weak` / `normal` / `critical`），渲染端拿这个档位去
「扣费反应」名单里取第 N 个动作播，同时在鱼身上飘出一个 **`-多少`**。金额不折算 —— 这笔账报的是什么
量纲，就飘什么量纲（见「每笔账的『-多少』」一节）。**档位不是动作名**：多大的账播哪一段是你在设置里
排的（见「动作 × 时机」一节），所以删掉名单里某个动作不会让这一档变成没反应。

阈值**由插件自己在 `meta.damage` 里声明**（`[[下限, 档位], ...]`，从高到低），`usage.js` 不再维护一张按来源 id 写死的表 —— 加插件不用改编排层。**下限的单位就是这个来源自己的量纲**，因为各来源报的账本来就不同：

| 来源 | 量纲 | `normal` 档起点 | `critical` 档起点 | 声明在 |
|---|---|---|---|---|
| WorkBuddy | 积分 | 0.1 | 0.5 | `providers/workbuddy.js` |
| DSH | 人民币 | ¥0.004 | ¥0.012 | `providers/dsh.js` |
| 手动记账 | 人民币 | ¥0.3 | ¥1 | `~/.whalepet/providers/manual-ledger.js` |
| Codex / Claude / ZCode | token | 2 万 | 6 万 | 各自的 `providers/*.js` |
| 不声明 | — | 1 | — | `usage.js` 的 `DEFAULT_DAMAGE` |

45 秒没有新账，信息条自动淡出到半透明。

### 数据源是插件

每个来源是 `providers/` 下的一个独立模块，可以随时**卸载 / 装回**；用户也能往 `~/.whalepet/providers/` 里放自己的插件：

```js
// providers/*.js 或 ~/.whalepet/providers/*.js
module.exports = {
  meta: {
    id, label, vendor, badge, paths, desc,
    unit: 'token' | 'credit' | 'CNY',          // 面板上显示用的单位
    fields: [{ id, label, unit?, desc? }],     // 可勾到信息条上的字段
    damage: [[下限, 档位], ...],               // 受击阈值，单位 = 你自己 emit 的量纲，可省
  },
  create(api) { return { poll(now, emit) {...}, raw(now) {...}, fields(now, ctx) {...} } },
}
```

宿主只注入一组小工具，插件**不直接 require 任何模块**，也不需要碰 Electron：

| 成员 | 说明 |
|---|---|
| `Tailer(file)` | 增量读追加内容的读取器 |
| `TailSet` | 管一批文件的增量读，并且直接告诉你这一行是**历史**还是**新到**（省掉每个插件手写 `armed` 开关） |
| `rollDay(now, state, onNewDay)` | 北京时间跨 00:00 时自动调 `onNewDay()` 清零当日累计 |
| `walkFiles` / `expand` | 递归找文件（可只取最近改过的）/ 展开 `~/xxx` |
| `bjDayKey` / `bjTodayStart` / `parseIso` / `num` | 时间与数值 |
| `UNIT_LABEL` / `withUnit(v, unit)` | 单位显示名 / 拼「值 + 单位」 |

**加一个插件只写它自己**：不用改 `usage.js`（阈值走 `meta.damage`、字段走 `meta.fields`、单位走 `meta.unit`），也不用改界面（`unit` 会自动渲染成数字后面的小字，`todayTokens` / `todayCredit` 会自动进「今日已用」合计，受击和飘数字全按你 `emit()` 里带的 `unit`／`amount` 走）。

### 每笔账的「-多少」＝ 掉血

大鱼吃白饭：**你花多少，它身上就掉多少血**。每笔账到账时鱼身上飘出一个 `-多少`，同时**整只鱼红闪一下**
（`pet.css` 的 `#pet.hurt`；暴击闪得更狠更久。真机抓帧：`tools/hurt-flash.png`）。

**掉血的口径**在 `usage.js` 的 `bloodOf()` / `hitOf()` 一处定义，飘字和面板都走它：

| 来源报的量纲 | 掉血数字 | 飘出来的样子 | 单笔量级 |
|---|---|---|---|
| `credit`（积分） | 原样，1 积分 = 1 点血 | `-0.09 积分` | 0.09 ~ 0.5 |
| `CNY`（人民币） | 原样 —— DSH / 手动记账报的本来就是钱（也就是「用余额表示」） | `-¥0.004` | 0.002 ~ 0.012 / 看你记多少 |
| `token` | **1,000,000 token = 0.01 点血** | `-0.0006 积分` | 1 ~ 8 万 token |

三件容易踩的事：

- **换算是只给飘字用的。** 受击档位（weak / normal / critical）仍然拿**各来源自己的量纲**去比它 `meta.damage` 里的阈值
  （`damageLevel()`）—— 否则动一下显示换算，会把「多大的账算暴击」一起改掉。`tools/test-hit.js` 两边都守着。
- **`fmtHit()` 的精度因此留到 1e-6。** token 源折算出来的数字天然很小（6 万 token → 0.0006），一刀切成「<0.001」
  会把所有 token 来源糊成同一个数，「掉了多少」就白飘了。
- **这是你定的换算率，不是价目表**：它不进账单、不影响「今日已用」，也不参与档位。想让 token 类来源更疼，
  改 `usage.js` 的 `TOKEN_BLOOD_PER_MILLION` 一个数就行（改成 10 就是 ×1000）。

#### 掉血的力度和节奏：照 `dsh-damage-pulse` 的口径抄

DSH 里那个正在跑的 `dsh-damage-pulse`（4.1.3，本机 `~/.dsh/profiles/*/node_modules/`）有一套现成的「扣血」做法，
桌宠这边按同一套口径对齐，省得两边对同一次扣费给出不一样的反馈：

| 它的做法（原参数） | 桌宠这边的落地 |
|---|---|
| **一笔账按「费用构成」拆成多条**：`命中 / 输出 / 未命中` 各飘一条，不合并成一个总额 | `providers/dsh.js` 的 `costParts()`：一笔账拆成 2~4 条，各带 `label`，飘字后缀就是它 |
| **档位按「这笔钱花在哪儿」定，不按金额**：`severity = kind === 'output' ? 1 : kind === 'normal' ? 2 : 3` | 未命中缓存 = `critical`（付的是全价输入）、命中 = `normal`、输出 / 缓存写入 = `weak`。插件通过事件里的 `level` 直接声明，`usage.js` 优先采信它 |
| **速率 → 连击**：两次重击间隔 < **900ms** 就是 `critical-combo`，抖得更狠 | `usage.js` 的 `markCombo()` / `COMBO_WINDOW_MS = 900` 给事件盖 `combo`；渲染端叠一档红闪 + 3px 左右抖动（`pet.css` 的 `#pet.hurt.crit.combo`） |
| **余额变多 = 复活**：15s 轮询余额，涨了就飘绿色 `+x` 并播 `revive-recharge` | `renderer/pet.js` 的 `watchBalance()`：比前后两次快照的余额，涨了就飘绿色 `+x元` 并播「打起精神」，同时停掉红闪 |

#### 节奏：扣费实时，余额 60 秒校准

这两条周期是**分开**的，也是照那个插件的口径（它 README 写「查询 DeepSeek 官方余额并每 60 秒校准；扣费事件到达时先逐笔更新显示余额」，客户端常量化就是 `CHARGE_POLL_MS = 1e3`）：

- **扣费 1 秒一轮**（`usage.js` 的 `POLL_MS`，原来 2500ms）。敢压到 1s 是因为一轮几乎不花钱：首轮要把当天日志读全文（实测 ~40ms），之后每个来源都走增量 tail，**一轮只要 1~4ms** —— `tools/check-poll-cost.js` 可复跑，1s 一轮约合单核 0.2%。嫌费电用 `WHALEPET_USAGE_MS` 调回去。
- **余额 60 秒校准一次**（`BALANCE_INTERVAL_MS`）。官方结算本身有延迟，查得更勤也只是拿到同一个数。
- **两次校准之间余额是动的**：每读到一笔 DSH 花费就先把显示值减掉（`balance.spentSince`），所以数字是「实时往下走、每 60s 回官方对齐一次」。只减 DeepSeek 自己的花费（`source === 'dsh'` 且量纲 CNY），WorkBuddy 的 credit 和第三方 token 都不动它。
- 快照里同时给两个值：`dsh.balance.value`（官方校准值）和 `dsh.balance.live`（实时显示值）。信息条上那一格用 `live`，而渲染端的「充值 → 复活」必须比 `value` —— 拿实时值去比会被自己的逐笔累减带偏（每笔扣费都像余额掉了，下一次校准又像涨了）。`tools/test-balance-live.js` 把这几条都钉住了。
- **首轮只播种、不报账**（`providers/dsh.js` 的 `state.seeded`）。账本是从头读的，冷启动时近 1 小时的账会**一次性**灌进来：一轮问答十几条记录，按费用构成还要再拆 2~4 条，实测启动瞬间就是 **543 条飘字**，队列（40 笔）当场被反复挤爆、控制台刷满「丢掉最旧的一笔」。这些账上一次运行时早就报过了，重播等于刷屏。口径和 `dsh-damage-pulse` 一样：它客户端也是先 `chargeSeeded` 播种，之后才开始受击。首轮那批也**不计入余额的实时累减** —— 它们已经含在官方校准值里，算了就是重复扣。

**两条解耦，别又缠回去**：档位（`level`）只管**播哪段动画**，飘字字号只管**金额**（`usage.js` 里另算的 `big`）。
一开始把字号绑在档位上，拆账之后就出现了「¥0.001 的未命中」字比「¥0.02 的输出」还大 —— 因为前者是重击、后者是轻档。
重击归动画，大小归钱。

**拆分不会动账面**：四项分项之和恒等于整笔 `cost`（实测 400/400 笔分毫不差，`tools/check-dsh-split.js` 可复跑）。
拿不到分项字段的记录退回整笔发一条，绝不漏掉一次扣费。

验收钩子：`WHALEPET_FAKE_SPLIT=1`（配合 `WHALEPET_FAKE_HIT=0.05`）会伪造「拆开的三个分项 + 一记连击 + 一条充值」，
`WHALEPET_PROBE=1` 会把渲染端 `#hit` 里每一行的**文案 / 颜色 / 字号**读回 `tools/startup-report.json`。
真机证据：`tools/blood-parts.png`。

**没有血条，也没有血量池。** 不累计、不设上限、掉到 0 也不会瘫倒 —— 「掉血」就是每一笔账各飘一个数字 + 红那一下。
所以它不需要任何持久化状态：重启之后不会「少一截血」，也不会因为你今天花多了就变哑巴。

**「算」全在主进程、「画」全在渲染端。** 主进程给出 `hitValue` / `hitUnit`（`usage.js` 的 `hitOf`），
渲染端只负责把它画出来、让它飘上去、让鱼红一下 —— 和 `fields` 一个道理。
`hitUnit` 除了单位还可能带一个**费用种类后缀**（如 `未命中`），拆账时靠它区分同一笔里的几条。

**一笔一个，不合并。** 主进程只按量纲排版，不做任何合计（`decorateEvents`）。一轮采集常常带回来十几条记录（一个用户回合会产生很多段模型调用），把它们加成一个「-3.5」虽然好读，但你就看不到底下其实是 `0.3 / 0.1 / 0.1 …` 那一串真实的扣费了 —— 而**看清钱一笔一笔在流出去**正是这个桌宠想做的事。

**拥挤交给渲染端，而且是竖着放的。** 桌宠窗口只有 ~380px 宽，一行 `-0.3 积分` 就占掉 70px —— 横向最多错开两三格，一次回来十几条就只能糊成一团红字（这个坑踩过，截图里是「-0.7-0.8 积分积分」叠在一起）。所以数字**竖排叠在鱼身上**：一笔一行，新的从下面顶上来，旧的自然往上走、淡出，读起来就是一张流水账。一行存活 ~0.95s，所以同时最多 5~6 行在屏上。队列超过 40 笔（一次 flush 回来几千条那种极端情况）丢最旧的并在控制台说一声 —— 丢的只是飘字，信息条上的「今日已用」该是多少还是多少。

**出场节奏 170ms 一笔，节拍挂在「上次出场的时间」上。** 逻辑在 `shared/hitpacing.js`（纯时间逻辑、不碰 DOM，所以 `tools/test-hit-pacing.js` 能用假时钟确定性地测它）。这里有个**踩过的坑**值得记一笔：一开始的写法是「队列里还有剩的才排下一次出场」，看上去等价，实则完全失效 —— 一次落盘带回来的十几笔是**同一瞬间**到的（一条 IPC 一个任务），每一笔到场时队列都是空的，于是每一笔都「立刻出」，十几行数字糊在同一帧上，排队等于没排。截图里就是一团红字。现在记的是 `lastAt`：下一笔至少隔 170ms 才允许出；真的空转（距上次出场已超过一个间隔）才 0 延迟立刻出，不让单独一笔白等。

**受击动画仍然只播一次，红闪不在此列。** 数字是一笔一笔的，整段受击动作不是：一波账里只有最重的那笔配得上完整的受击动作，否则十几笔会互相打断成一片乱抖。**红闪（`flashHurt`）每一笔都闪** —— 它是「这一笔掉了血」的即时反馈，跟着飘字走，不跟着动画走。「最重的那笔」比的是**档位**（`weak` < `normal` < `critical`），不是金额 —— 三个来源量纲不同，金额没法比。

**这是流水，不是指标。** 所以信息条上没有「今日共扣了多少」这一格，`usage.json` 里也只有「装了哪些插件」和「显示哪些字段」两项 —— 平台不记账、不累计、也不按累计量改形象。

`providers/_template.js` 是能跑的骨架，`providers/README.md` 是完整说明（含可复制的最小示例）。**下划线开头的文件不会被加载** —— 想临时搁置一个插件，把它改名成 `_xxx.js` 就行。

单个插件语法错 / 抛异常只会让它自己显示「装载失败」，其余照常工作 —— 桌宠不会因为一个第三方插件变砖。加载错误会显示在设置窗口「数据源插件」底部的红条里。

装没装存在 `usage.json` 的 `installed` 里；卸载一个插件时它声明的字段会自动从信息条上摘掉，重新安装后回到「可添加的字段」（配置里的引用不会丢，插件放回来字段也跟着回来）。

### 一个现成的用户插件示例：手动记账

桌宠自带一个装在**用户目录**里的插件，它既是示例、也是真能用的兜底：

| | |
|---|---|
| 插件 | `~/.whalepet/providers/manual-ledger.js` |
| 账本 | `~/.whalepet/ledger.jsonl`（一行一条 JSON，`#` 开头的行当注释跳过） |

网页版 ChatGPT / Gemini、包月订阅这类**不在本机留日志**的服务，往里记一笔就能进信息条：

```powershell
Add-Content -Encoding UTF8 "$HOME\.whalepet\ledger.jsonl" '{"at":"2026-09-30T21:10:00+08:00","service":"ChatGPT 网页版","cost":1.25}'
```

字段「手动记账」默认**不显示**，在设置里点「＋ 手动记账」加进去。它在设置里标着「用户插件」，多一个「删除文件」按钮：删掉只删那一个 `.js`，`ledger.jsonl` 会留着。想改成自己的需求，直接编辑那个文件再点「重载插件」即可（不用重启）。

### 一次「凭空多出来的 ¥1.25 / 1.8 万 token」

用户报过：一路只用 WorkBuddy（积分制），用量面板里却多出一条 **1.8 万 token · ¥1.25 · 2 次**。查下来的结论是**测试脚本的账目被桌宠当成了真实消费**，链条是这样：

1. `tools/test-user-plugin.js` 要验「跨天过滤 / 受击档位」，会往 `~/.whalepet/ledger.jsonl` 写三条临时账目（昨天 ¥99、今天 ¥1.25、今天 18000 tokens）。
2. 但**桌宠可能正在运行** —— 它一 poll 就把这两条当成真实消费，写进 `usage-history.json`。
3. 用量账本是**按天累加、且每项取历史最高值**（`shared/history.js` 的 `merge` 用 `Math.max`，这是为了让「重启一次当天数字不掉」），所以事后把账本还原，也**擦不掉**已经记进去的数。用户看到的就是一条永远消不掉的幽灵记录。

修法不是"改完再还原"，而是**让测试根本碰不到真实文件**：`providers/api.js` 里把「插件眼里的家目录」抽成一个可覆盖的 `PLUGIN_HOME`（`WHALEPET_HOME` 环境变量），`providers/index.js` 的用户插件目录也跟着它走，测试则把自己关进 `mkdtemp` 出来的临时目录、只把用户插件**只读拷**进去。跑完整个临时目录删掉即可 —— 顺带把那套「备份→还原」也删了：它本身有毒（上一次被 Ctrl-C 留下的测试账本，下一次会被当成"用户的原样"再写回去）。

验收：跑测试前后 `md5sum ~/.whalepet/ledger.jsonl` 必须一模一样，`~/.whalepet/providers/` 里也不许多出文件 —— `tools/test-user-plugin.js` 现在是 **25 项全绿**且真实文件零改动。

> 教训：**测试要动用户文件时，隔离比还原可靠。** 还原只在"测试是唯一在场者"时成立，而这个应用恰恰有一个常驻进程在旁边读同一个文件。

它同时也是**插件契约的一个活样板**：`meta.damage` 阈值、`meta.unit`、`Tailer` 增量读、`fields()` 里用 `ctx.fmtTokens` 做格式化、以及「首轮不发事件」都在这一个文件里能对照着看。

### WorkBuddy 为什么要读两个源

credit 有两个源，各有短板，所以**都读、按 `rootRequestId` 合并、取较大值**：

| 源 | 覆盖范围 | 时效性 |
|---|---|---|
| 运行时日志的 `[SessionManager][credit] Credit received` | **全** —— 所有会话的每一笔调用 | 攒一批（约 512KB）才落盘，活跃时也要 1~5 分钟才看到新账 |
| `~/.workbuddy/workbuddy.db` 的 `session_usage.credit_json` | 只有**当前 session** | 边跑边写，秒级 |

只靠日志，表现就是「钱都花完了数字还不动」；只靠 db 又会漏掉别的会话（db 里每个 session 一行）。合并时两边各记一份，同一个 `rootRequestId` 取较大者 —— 谁先到都只涨一次，不会重复计。

读 db 有个坎：本桌宠跑在 Electron 33（Node 20.18），**没有内置 `node:sqlite`**（要 22.5+），WorkBuddy 自带的 `better-sqlite3` 又按别的 ABI 编（`NODE_MODULE_VERSION` 对不上）。所以 `api.sqliteQuery()` 去借 WorkBuddy 自己那个 Node（`~/.workbuddy/binaries/node/versions/<版本>/`）起一次性子进程、异步拿回结果；**借不到就静默退回日志源**，功能一点不受影响，只是数字慢一点。

`~/.workbuddy/projects/**/*.jsonl` 里**没有 credit** —— 在那儿能 grep 到的 `credit` 全是「工具输出把日志正文又写回 jsonl」的自引用，所以 credit 没走那条路。但它有上面两个源都没有的东西：每次调用的**缓存命中**字段，所以缓存命中率单独走了这个源。

### 缓存命中：数据在 jsonl 里，但文件很大

`projects/<工作区>/<会话>.jsonl` 每条模型调用是一行 JSON，`providerData.rawUsage` 里有：

```
"prompt_cache_hit_tokens":35200,"prompt_cache_miss_tokens":415
```

命中率 = `hit / (hit + miss)`。命中的那部分按缓存价计费，所以这个数字越高越省（实测一整天在 99% 上下）。

难点不在解析，在**文件大小**：单个会话文件实测累积到 **65MB**（跨两天），而「今天」的记录只占末尾 ~11MB。整份读一次要几百毫秒，会把主进程卡住（桌宠的拖动、定时器都跟着顿）。jsonl 是按时间追加的，今天的记录必然在末尾，所以首次接入时**从文件尾部按 1MB 块往回扫，读到一条更早的记录就停** —— 读到的量正好等于今天那一段（实测 12.6MB / 92ms），之后交给 `Tailer` 增量跟（每轮 2~6ms）。

三个配套细节：

- **取时间戳必须锚在行首**（`^\{"id":"…","parentId":…,"timestamp":`）。整行搜 `"timestamp":` 会取到工具输出回显进来的别的 JSON。
- **不必 `JSON.parse` 整行**：缓存字段全部落在 `rawUsage` 开头 1.2KB 内（实测 1568 行无一例外，且与解析出来的真值逐条一致），而整行动辄上百 KB。
- **末尾压着半行时退到最后一个换行之后**。那一行还在写，现在算不准，`Tailer` 也不能从行中间接起。

今日合计由各文件的**子账求和**得出，不是累加值 —— 和上面 credit 的账本同一个思路：文件万一被截断重建，只重置它自己那一份，合计不会算重。

DSH 的原始会话是 `~/.dsh/sessions/**/session.v4.jsonl.zstd` —— **zstd 压缩，Node 20 内置模块没有解码器**（`node:zlib` 只到 gzip/br/deflate）。它的 `dsh-token-monitor` 账本是等价的明文副本，直接读那个。

日志读取踩过的坑都在 `providers/api.js` 和各插件的注释里，改之前先看：

- **尾部读取必须循环 `readSync` 直到没有剩余字节。** 单次 `readSync` 不保证读满（3MB 的会话日志一次只拿回一部分），而 `offset` 一旦推到 `stat.size`，没读到的部分就永久丢了。
- **`Credit received` 是增量的，不是一个请求一行。** 同一个 `requestId`（一次用户回合）会陆续写几百行，每行是**一次模型调用**的结算，必须逐条累加。按 `requestId` 去重会把一整天的账压成十几条 —— 实测 1254 行 / 138.97 积分被算成 13 行 / 9.03，桌宠上的积分因此几乎不涨、也跟不上正在花的钱。去重键得用「行时间戳 + 请求 id + 金额」：既能逐条计入，又能在日志轮转后（同一行同时存在于 `xxx.log` 和 `xxx.old.log`）认出是同一笔。
- **两个源归日要用同一把尺子。** db 的 `credit_json` 只有 `{rootRequestId: 金额}`、没有时间，但那些 id 是 **UUIDv7**，前 12 位 hex 就是毫秒时间戳，能还原出回合**开始**的那一刻。日志那边则取行首时间戳。两边都按「回合开始的那一刻」归日，一个横跨午夜的回合才不会被两边的口径算成两天。db 里还混着少量非 v7 的 id（前 12 位当时间戳会算出天外飞仙的年份），所以校验了 2015~2100 的范围，认不出来的只在日志登记过它时采信。
- **日志会被自己污染。** 用工具打印日志内容时，WorkBuddy 会把这段输出又写回同一个日志；所以正则一律**行首锚定**（`^\[`）。
- **一天里有多个会话日志。** 上下文只认最新的那一份（按每行时间戳比对），否则会读到旧会话的数值。首次见到某个日志文件时只累计历史、不发事件，避免启动瞬间炸一堆动画。
- **Claude Code 的日志里大量 `message.model === "<synthetic>"`**，usage 全是 0，必须跳过，否则「今日次数」会被空行灌水。
- **ZCode 的 model-io 文件很大**（单会话 1.5MB 起，`request.body` 里塞了完整 system prompt 和全部 tool schema），所以先做字符串预筛（`"usage"` + `"completedAt"`）再 `JSON.parse`。

### 隐私

余额需要 DeepSeek API key，本桌宠**只读**它、只用于本地发起一次 HTTPS 查询，不写入任何地方、不发给第三方：

- 优先取环境变量 `DEEPSEEK_API_KEY`；
- 否则从 `~/.dsh/.credentials.yaml` 里正则取出同一字段（只读该文件，不改写）。

不想联网就设 `WHALEPET_NO_BALANCE=1`。DSH 那半边的账是直接读插件自己的 `usage.jsonl`，不联网。

**所有插件都只读**日志和本地库，不写任何文件、不改原插件目录。

## 用量面板（独立窗口）

右键菜单 / 托盘 →「用量面板…」。它和设置窗口是**两个独立窗口**，各开各的。

为什么要单独开一个窗口：桌宠脚下那条信息条是**给一眼瞥过去用的**，只能放几个数；而「这个月比上个月多花了多少」「缓存命中是不是变差了」这类问题需要**历史**和**曲线**，那不是一条 30px 高的胶囊条能承载的。

### 四个分页

| 页 | 里面是什么 |
|---|---|
| **概览** | 今日四个数字（token / 积分 / 金额 / 调用次数）+ 最近 7 天的小折线 + 各来源速览 |
| **每日** | 30 天（可切 7/14/30）折线图，指标可切 token / 积分 / ¥金额 / 次数；下面是一张逐日明细表 |
| **来源** | 每个数据源一张卡片：今日明细（输入/输出/推理 token、**命中/未命中 token 与命中率**、最近模型、上下文占用）+ 最近 30 天累计 |
| **字段** | **原来在设置窗口里的「桌宠上显示」搬到了这里** —— 桌宠脚下显示哪些字段、什么顺序 |

### 每日用量是怎么攒出来的

各插件报的都只是**「今天」的累计值**（`raw()` 里的 `todayTokens` / `todayCredit` / `todayCost`），过了零点就归零 —— 历史不自己存下来，就永远只有一天，画不出趋势。

账本在 `shared/history.js`（`<项目>/usage-history.json`，已在 `.gitignore` 里）。要点：

- **记的是「当日累计的最新值」，不是增量**。同一天里反复覆盖同一行，跨天自动开新行 —— 这样中间丢几轮 poll 也不影响结果，下一轮的累计值本来就包含前面那些。
- **逐项取 `max`**：插件被重载后它的累计器是从零重建的，中间有几百毫秒会报出比刚才小的数（实测 WorkBuddy 重载后短暂报 0）。直接覆盖的话，那一下就把当天已攒的量抹掉了。
- **记账写在 `broadcastUsage` 里，不在面板里**：面板没开的时候也得攒，否则用户不开面板就永远没有历史，等他打开时图上只有今天一个点。
- **落盘节流 15 秒**，退出时 `flush(true)` 强制写一次。
- **量纲不换算**：token 是 token，积分是积分，人民币是人民币。三种分开记、分开画 —— 折起来要拍一个单价，那个数字写进代码就会过时，而且「我到底用了多少 token」这本账会变成答不上来的问题。
- 文件坏了 / 版本对不上 → 当空账本重新开始。**这是统计历史，丢了不该拦住桌宠启动。**

### 一个刻意的分工

`history.js` 的 `series` **只包含账本里真有的日期**（不凭空造日期：账本不该写没发生过的天）。但折线图需要一条**等距的时间轴**，所以补零这一步放在**面板层**（`panel.js` 的 `dlRows()`）—— 只给有记录的那几天的话，月初只有一条数据时横轴就一个点，看不出趋势。

## 配置

`config.json`（自动生成）：位置 / 大小 / 置顶 / 形象 / 动作时机

```json
{
  "x": 1280,        // 窗口位置（拖动后自动保存）
  "y": 460,
  "scale": 0.7,     // 0.7 小 / 0.9 中 / 1.1 大（默认小）；超过上限会被夹回来，见「尺寸」
  "alwaysOnTop": true,
  "skin": "shayu",
  "triggers": null  // 时机 -> 有序的动作 id 名单；**和默认一样就是 null**。
                    // 只记你改过的那份，例如把「双击」换成别的：
                    // { "click": ["acting"] }
}
```

`triggers: null` 意思是「全走默认」（默认名单见「动作 × 时机」一节）。这样以后调默认搭配时，
没动过的那些不会被一堆历史记录压住。老版本写的 `actions: { "hips": false }` 会在读取时
自动换算到名单上，然后那一栏就删掉了。

`usage.json`（在设置里改，自动生成）：插件装没装 / 信息条字段与顺序
`usage-history.json`（自动生成）：每日用量账本，用量面板的折线图靠它（见「用量面板」一节）

```json
{
  "installed": { "workbuddy": true, "dsh": true, "codex": true, "claude": true, "zcode": true },
  "fields": ["today", "ctx", "workbuddy", "dsh"]
}
```

`installed` 里没有的键默认视为「已安装」（`false` = 已卸载）；旧版本的键名是 `enabled`，含义一样，读到会自动转换，不用手动改。`fields` 里引用了不存在的字段 id（插件被卸载/删了）会**跳过而不删配置**，插件装回来字段也跟着回来。

## 常见问题

- **背景不是透明的**：显卡驱动异常时 Electron 可能回退软渲染，透明仍然正常；若出现黑底，先按上面「沙箱与硬件加速」调 `WHALEPET_SANDBOX` / `WHALEPET_GPU`。
- **双击后窗口一闪就没、或报 `'xxd' 不是内部或外部命令`**：启动脚本被存成了 UTF-8 或 LF。用 `python tools\make-launchers.py` 重新生成。
- **双击了但桌宠不出现，任务管理器里却有几个 electron.exe**：多半是 `%~dp0` 尾斜杠把参数搞坏了（见上面第②条），重新生成启动脚本即可。
- **双击了没任何反应**：先看 `tools\startup-report.json`（需 `WHALEPET_REPORT=1` 启动）里有没有 `did-finish-load`。
- **从终端直接跑 `electron.exe .` 报 `Cannot read properties of undefined (reading 'commandLine')`**：环境里带了 `ELECTRON_RUN_AS_NODE=1`（WorkBuddy 的 bash、某些 CI 都会带），`electron.exe` 于是以**纯 Node** 身份运行，`app` 是 undefined，进程立刻退出且什么都不打印。跑之前 `unset ELECTRON_RUN_AS_NODE`（`tools\verify-panel.py` 里已显式摘掉）。双击 `.bat` 不受影响。
- **验收结果里出现「a 段跑了两遍」「同一张图抓了两次」这种看不懂的重复**：`tools/startup-report.json` 是**一个固定文件、整份覆盖写**。只要还有一个旧实例活着（手工 Ctrl-C 掉、或上一次崩了都会留下），两个进程就会轮流覆盖它，验收脚本于是读到「一半自己的、一半别人的」步骤。报告里现在带 `pid`，验收脚本用**自己拉起来的那个进程的 pid** 认领报告，不是它写的就当空；两处验收脚本也都会在启动前先 `taskkill` 一次。手工排查时如果结果反直觉，先确认 `tasklist | grep electron` 只有 4 个进程。
- **拖起来的时候形象看着像两个头**：那是旧形象那张「拎起帧」素材的姿势问题（已在换形象时删除），拖动时不再切图，不会复现。
- **想换大小 / 换形象**：右键 →「设置…」→ 外观，或直接改 `config.json` 的 `scale` / `skin`。改大小是**底边不动**地缩放，桌宠不会跳。
- **位置跑出屏幕外**：删除 `config.json` 后重启，会回到右下角默认位置。
- **想自己验一次拖动**：`python tools\drag-verify.py poll 16 24 9`，会在 `tools\ab\` 下留一组真实桌面截图；再跑 `python tools\make-evidence.py poll16` 拼成对照图。
- **想自己验一次启动脚本**：`python tools\verify-bat.py`，会按双击的方式启动并截图，确认「双击」这条路真的通（4 个进程 + 真实桌面截图）。跑完会把测试实例关掉、并把 `config.json` 还原成你原来的样子，所以不会把你的桌宠挪位置。
- **想自己验一次完整功能**：`python tools\verify-panel.py`，会启动桌宠、抓窗口图、伪造一次暴击扣费、开设置窗口，**并在窗口里真点一遍按钮**（切大小 / 加字段 → 上移 → 移除 → 卸载 → 安装 → 重载 / 动作页里去掉·加回·排序·试演），最后把断言结果和截图一起打出来。跑完会自动还原 `usage.json` 与 `config.json`，不会改掉你在设置里做的选择 —— 动作页那段跑完还会**硬断言**五张卡片的名单都回到了默认，因为验收中途会真的改你的搭配。
- **想一次跑完全部纯逻辑自测**：`npm test`（= `test-triggers.js` → `test-hit.js` → `test-hit-pacing.js` → `test-scale.js` → `test-cache-hit.js` → `test-usage-history.js` → `test-providers.js` → `test-user-plugin.js`）。不启动 Electron，也不碰你的配置，几秒钟出结果。
- **想自己验一个用量插件**：`node tools\test-user-plugin.js`，会往账本里临时塞三条账目（含一条昨天的，验证跨天过滤）、检查事件档位、再试一次卸载/重新安装/删除，跑完把账本和 `usage.json` 都恢复原样。**这个脚本和 `test-providers.js` 必须串行跑**：前者会临时改写 `~/.whalepet/ledger.jsonl`，两个同时跑的话，后进来的那次会把「前一次塞进去的测试数据」当成原始账本备份、退出时再写回去，你的账本就被静默换掉了。脚本用 `~/.whalepet/.ledger-test.lock` 挡这件事（持有者已死会自动接管，所以上次被打断不会把你锁在外面）；`test-providers.js` 是只读的，不加锁，但看到锁会打印一行提醒。
- **信息条上的数字单位看不懂**：WorkBuddy 那一格是**积分**（它自己按 credit 计费），其余是 **token**。两个单位**不做换算**（1 积分 ≠ 多少 token，各家的计价口径并不通用），所以「今日已用」会并排写成 `5564.2万 token · 0.520 积分`。
- **卸载了一个插件，还想把它的字段放回信息条**：先「安装」把它装回来，字段就会回到「可添加的字段」里，再手动点 ＋ 加上去。**不会**自动塞回去 —— 否则排好的顺序会被悄悄改掉。
- **信息条不出现**：先确认没设 `WHALEPET_USAGE=0`；再 `node tools\test-providers.js` 看每个插件能不能读到数据（会打印「可用 / 无数据」和细节）。
- **某个来源一直显示 `--`**：在设置窗口里看那张卡片的状态行。Codex / ZCode / Claude 只有**最近几天**（3~7 天）有文件时才扫，`node tools\test-providers.js` 加 `WHALEPET_TEST_DAY=2026-09-29` 可以「时间旅行」到某天验证解析本身对不对。
- **自己写的插件不生效**：设置窗口「数据源插件」页底部的红条会显示加载失败的原因（语法错、缺 `meta`、`create` 抛异常）。改完点「重载插件」，不用重启。也可以先 `node tools\test-providers.js` 看它有没有被装进来。
- **桌宠本体不见了，信息条还在但数字停在 `--`**：渲染端脚本一抛异常就整段停摆，页面上只剩样式表，桌面看不出任何提示。用 `WHALEPET_REPORT=1` 启动，`tools\startup-report.json` 里会有 `renderer:console` 记下具体报错和行号（`renderer/pet.js` 已把 `error` / `unhandledrejection` 桥到 `console.error`）。
- **余额一直是 `--`**：多半是拿不到 key 或没联网。`node tools\test-balance.js` 单测接口；不想联网就设 `WHALEPET_NO_BALANCE=1` 把余额那格变成 `--`，其余照常。
- **扣费了但傻鱼没反应**：先看设置 →「动作」→「扣费反应」里还有没有动作 —— 那一组空了就真的不会播。其次看日志时间戳与系统时间差是否超过 1 小时（旧账会被丢弃，避免翻旧账）；确认对应的客户端正在跑并且写的是今天的日志。也可以用 `WHALEPET_FAKE_HIT=3.5 WHALEPET_FAKE_LEVEL=critical WHALEPET_CAPTURE=1` 单独验一遍「事件 → 动画」这条链路（`FAKE_LEVEL` 给的是档位，会被换成名单里第 3 个动作）。
- **信息条的高度对不上（数字被裁掉 / 底下空一块）**：渲染端量完实际高度会回报给主进程（`usage:bar-height`），主进程保持**底边不动**地把窗口长上去。若手工改了 `pet.css` 的 padding，确认 `pet.js` 里 `reportBarHeight()` 的 `+12+6` 余量还匹配。
- **验收脚本报「自检跑了 5 段（应为 3）」，或者断言总数比平时多**：`verify-panel.py` 跑的时候**别碰桌面**。自检链是挂在设置窗口 `did-finish-load` 上的（a → b → c），验收期间只要有人真的点了桌宠、把设置窗口关掉又打开，窗口一重建就**又从头跑一遍**，报告里于是混着两条链的步骤（实测出现过 `a、b、a、b、c`）。这种报告里的「53/53」只是两遍里各挑了一遍的结果，所以脚本会把「段数 ≠ 3」直接判成失败并提示重跑 —— 看到了就关掉手重跑一次，别去调断言。
- **验收脚本抓到的设置窗口图是空的（`capturePage()` 返回 `0×0`）**：Windows 会把「被别的窗口完全盖住」的窗口判为 *occluded*，Chromium 随之**停止提交新帧**，于是抓图稳定为空 —— 而 `isVisible()` 是 `true`、`getBounds()` 也完全正常，光看窗口状态查不出来。桌宠因为 `alwaysOnTop` 从不被盖住，所以只有**设置窗口**会中招，而且时好时坏（取决于当时谁在最前面）。`main.js` 的 `captureWindowTo()` 有三道保险：抓之前把目标窗口**临时置顶**（抓完还原）、`webContents.invalidate()` 主动要一帧、再重试到拿到非空图；验收模式还会开 `disable-backgrounding-occluded-windows`。自己写抓图逻辑时别绕开它。失败时 `startup-report.json` 里的 `capture:empty` 会带上 `visible / minimized / offscreen / bounds`，先看那四个值能把「没显示」「最小化」「跑到屏幕外」「单纯被盖住」区分开。

## 与 DSH 插件的关系

本桌宠的 `dsh` 数据源**只读**消费 DSH 插件 [dsh-damage-pulse](https://github.com/wssfk12138/dsh-damage-pulse)（其中的 `dsh-token-monitor`，负责记录 token 消耗）写下的数据。插件本体、它的安装目录和 token 记录都**没有被改动**，两者互不影响：

- 插件安装位：`~/.dsh/profiles/{desktop,web}/node_modules/dsh-damage-pulse`
- token 记录：`~/.dsh/data/dsh-token-monitor/`（`usage.jsonl` / `request-details.jsonl` / `state.json`）
- 源码仓库：`~/.zcode/workspace/default/dsh-damage-pulse`

本桌宠只做**只读**消费：`providers/dsh.js` 读 `usage.jsonl` 里的当日 `cost`（按 `sessionId + sourceEventSeq` 去重），读 `~/.dsh/.credentials.yaml` 里的 key 调一次余额接口。不写回、不修改插件任何文件。
